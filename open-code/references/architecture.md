# Architecture

ADAPTIVE ARCHITECTURAL SYNTHESIS: Dynamic system architecture modeling governed by: requirement specification, runtime stack, framework paradigms, functional boundaries, algorithmic complexity, dependency DAGs, and scale trajectories. Zero universal template dogma. Invariants: Minimum Sufficient Organization, High Functional Cohesion, Low Coupling, and Strict Separation of Concerns. Architectural layers, modular boundaries, and abstractions are materialized if and only if justified by structural necessity. Prohibited: speculative abstraction, artificial fragmentation, and redundant hierarchical nesting.

PROJECT ARCHITECTURE MAP (TOPOLOGICAL SOURCE OF TRUTH): Authoritative structural representation serving as system navigation map and dependency matrix. Captures: topological graph, component boundaries, interface signatures, entry points, dependency flows, and execution pathways. Artifact selection anchored strictly to existing repository topology without redundant documentation. Tripartite Architecture Model: strict differentiation between `Intended Architecture`, `Implemented Architecture`, and `Verified Architecture`. Deterministic topological synchronization post-mutation.

ARCHITECTURAL DRIFT DETECTION & CONTINUOUS RECONCILIATION: Continuous delta analysis between: `Intended Architecture`, `Implemented Architecture`, `Verified Architecture`, and `Project Architecture Map`. Automatic identification of: structural drift, hidden/undocumented dependencies, stale specifications, boundary leaks, and semantic divergence. Documentation never constitutes verification. Discrepancies enforce immediate reconciliation workstreams.
